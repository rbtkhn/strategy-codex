## Why This Belongs Here

The compute-futures bridge changes the roadmap question. The issue is no longer only whether agents get smarter. It is whether this project is preparing for a world where substrate, finance, distribution, trust, and control-plane burden all move together.

That shifts the roadmap away from "more AI features" and toward a harder design target:

**becoming a substrate-aware operating system for judgment under acceleration**

## Five Roadmap Implications

### 1. Compute and substrate governance should become a first-class track

The bridge note implies that compute is becoming more legible as a governable and possibly financeable substrate. If that is right, the project should spend more time on:

- compute sovereignty
- infrastructure dependence
- energy and data-center bottlenecks
- who owns capacity versus who merely consumes model output

This is a `possible-climb signal`, not a mature doctrine. But it is strong enough to justify a dedicated roadmap lane.

### 2. Agent control matters more than agent cleverness

If capital can scale substrate faster, agent concurrency may rise faster than human oversight. That makes the control plane more important than benchmark theater.

Roadmap weight should continue to favor:

- permissions
- receipts
- rollback
- observability
- operator authority

This is where singularity-academy and `work-dev` most clearly touch.

### 3. Interface work should be judged by operating-layer residency

The workshop sources keep pointing toward interface collapse into an operating layer. That means roadmap judgment should ask:

- does this become a daily operating surface?
- does it reduce activation energy?
- does it capture durable workflow residency?
- does it preserve the human gate when the interface becomes ambient?

This makes `work-cici`, onboarding, chat-native scaffolds, and narrow public-interface pilots more central than they may first appear.

### 4. Trust infrastructure is part of the core build, not polish

The provenance front keeps recurring across the Moonshots and Innermost Loop sheets. That means roadmap work should keep treating:

- freshness signaling
- visible source discipline
- graceful degradation
- proof-linked public output

as core design features rather than cleanup.

This remains a `foothills signal`, but it is already strong enough to change build priorities.

### 5. Bridge notes and doctrine notes are now core output, not side products

The workshop is proving most useful when it does not merely collect source sheets, but turns them into:

- bridge notes
- control-plane cases
- doctrine notes
- live-lane tests

That means the roadmap should keep funding synthesis infrastructure, not only raw capture.

## Action Wedges

### 1. Compute / substrate governance

- **Next build:** a compact `compute as control plane` note or dashboard that tracks capacity dependence, energy dependence, and ownership-versus-usage risk across active lanes
- **Next test:** run one `work-dev` or `work-business` project through a substrate audit and see whether the result changes design or vendor choices
- **Failure condition:** rerank this lower if substrate analysis stays interesting but does not change live decisions across any active lane

### 2. Agent control-plane maturity

- **Next build:** one tighter control-plane surface with explicit permissions, receipts, rollback, and operator-visible escalation paths
- **Next test:** put a real recurring workflow through that surface and measure whether authority stays clearer under pressure, not just whether automation rises
- **Failure condition:** rerank this lower if the control-plane layer stays elegant in doctrine but does not improve real operator leverage or safety

### 3. Interface-as-operating-layer pilots

- **Next build:** one narrow pilot where chat, memory, action, and follow-up live in the same daily operating surface
- **Next test:** watch whether a real user or cohort actually returns to it as a default surface rather than as a novelty tool
- **Failure condition:** rerank this lower if the pilot does not create durable workflow residency or lowers trust in the human gate

### 4. Trust / provenance / graceful-constraint infrastructure

- **Next build:** visible freshness, provenance, and degraded-state signaling on one operator-facing surface
- **Next test:** force a thin-context or stale-source condition and verify that the surface narrows honestly instead of bluffing coherence
- **Failure condition:** rerank this lower if the doctrine is sound but no public or operator-facing surface actually embodies it

### 5. Beginner and cohort activation surfaces

- **Next build:** one daily or weekly scaffold that helps a novice or cohort take the next step without surrendering judgment
- **Next test:** measure whether the scaffold increases re-entry, artifact completion, or reply quality rather than only producing more traffic
- **Failure condition:** rerank this lower if activation rises but judgment, proof, or follow-through gets weaker

## Cross-Lane Consequences

### work-dev

Push harder on agent control-plane maturity, substrate observability, local-first resilience, and graceful-constraint behavior under degraded runtime conditions.

### work-cici

Treat cohort scaffolds, daily brief surfaces, and beginner-safe orchestration as singularity test cases, not just support work. The question is whether agency can be widened without surrendering judgment.

### work-business

Treat venture surfaces as experiments in labor compression, judgment leverage, and substrate dependence. The business lane is where recursive improvement either becomes real or stays rhetorical.

### singularity-academy itself

Keep building the keystone helix method:

- raw source capture
- source sheets
- bridge notes
- doctrine notes
- live comparisons across WORK lanes

## Priority Order

If this bridge is read correctly, the near-term roadmap order becomes:

1. compute / substrate governance
2. agent control-plane maturity
3. interface-as-operating-layer pilots
4. trust / provenance / graceful-constraint infrastructure
5. beginner and cohort activation surfaces that can survive scale

This ordering is a workshop inference. It should be revised when source pulses stop supporting it.

## Boundary

- Do not treat this note as proof that compute financialization is already mature.
- Do not let substrate focus erase the human office; the project still exists to preserve judgment under acceleration, not merely to admire infrastructure.
- Do not use roadmap coherence as a substitute for live tests in `work-dev`, `work-cici`, or `work-business`.
- Do not drift into summit language. The honest horizon is still `possible-climb signal` with several strong `foothills` fronts beneath it.
