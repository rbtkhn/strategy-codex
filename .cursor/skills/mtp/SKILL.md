# MTP — Massive Transformative Purpose orientation

**Preferred activation (operator):** say **`mtp`**.

**Aliases:** `massive transformative purpose`, `exo mtp`, `mtp orient` (accept *transformational* in speech; canonical term is **Transformative**).

Use this skill to **govern speed with purpose** before scaling automation, shipping large slices, promoting skills, or narrowing overloaded threads. Default lane: **Think** — no repo edits unless the operator upgrades (`EXECUTE`, `persist to sheet`).

## When to use

- Bare **`mtp`** or purpose drift before a big ship or automation change
- After **`ideation-engine`** — filter the winner with a pivot test
- Pre-ship wedge before **EXECUTE** or multi-file commit
- **Delete-legacy** pass (EXO step 2) when bureaucracy is being digitized instead of deleted
- Workshop / organizational-singularity sheets need a **why** governor before verify tables

## When not to use

- Replacing lane-specific diagnosis (**statecraft-framework**, **wire-verify**, **fact-check**)
- Every chat turn (becomes tagline theater)
- Record merge, gate staging, or public publish without explicit operator lane upgrade
- Glossary recitation only — run the full output shape below

## MTP sentence rule

The **one-sentence MTP must not name specific export products, tools, or vendors** (no product proper names in the sentence). Export surfaces belong under **Layer split** or **Falsifiers** only.

## Workflow

1. **Name the object** — one line (host, org, venture, sheet).
2. **Draft MTP candidate** — exactly one sentence.
3. **Pivot test** — pass/fail: *If every product line pivoted tomorrow, would this sentence still explain why it exists?*
4. **Not MTP** — tagline, OKR theme, product pitch, or abundance-only frame if confused.
5. **EXO stack diagnosis** — weakest step among: design MTP · delete legacy · intelligence stack · scale.
6. **Delete legacy** — 2–4 things to stop digitizing or treating as purpose.
7. **Falsifiers** — at least 3 rows: id · claim · signal that would disprove.
8. **Layer split** (when applicable) — Layer 0 system MTP vs subordinate export MTPs; never embed export names in Layer 0.
9. **Next move** — one reversible action; no auto-ship.

## EXO stack order (Salim)

1. Design MTP  
2. Delete legacy (do not digitize bureaucracy)  
3. Redesign around the intelligence stack  
4. Then scale  

Scaling before MTP + legacy delete → **pathology** (faster automated bad decisions).

## Verification / Proof Standard

Do not call this complete unless:

- Object is named in one line
- MTP is **one sentence** with **no product/export proper names**
- Pivot test is explicit pass or fail with one-line reason
- At least **3 falsifiers** with observable signals
- EXO bottleneck step named when scale-pathology risk exists

Evidence to report:

- Pivot test verdict
- Weakest EXO step
- Top falsifier most likely to fire near-term

If verification cannot be completed:

- State what was not read or verified
- Downgrade to generic EXO vocabulary pass
- Ask operator to name object or pick A/B/C
