# Statecraft multi-lens

**Preferred activation (operator):** say **`statecraft multi-lens`**.

Use this skill when the live object is already named and the real task is to divide explanatory responsibility across multiple statecraft lenses rather than to keep summarizing one speaker at a time.

This is a **comparison-and-diagnosis** skill. Its default output is a bounded analysis in chat, not note-writing by default.

## Use this skill when

- one statecraft object should be read through more than one lens
- the operator wants to know what each lens contributes and misses
- the object may be oscillating between trap, threshold, architecture, legitimacy, and order-transition questions
- single-speaker summary is no longer enough
- the combined read might change the next retrieval or drafting move

## Do not use this skill when

- the object is still unverified or unnamed
- the task is archive intake
- the task is day-batch synthesis
- the main need is governing-pair diagnosis rather than lens comparison
- the operator already knows the right lens and wants direct drafting instead

## Core law

This skill compares a **shared object**, not a set of personalities.

Ask:

- what does each lens see best?
- what does each lens miss?
- what becomes visible only in combination?
- what next surface becomes more appropriate because of the comparison?

Short rule:

`do not ask only who is right; ask where explanatory responsibility is divided`

## Canon size rule

This skill intentionally ships with a very small permanent pack set.

Permanent canon includes only:

- one **dual-lens** pack
- one **tri-lens** pack

Do not treat every useful comparison as a permanent pack.

At the same time, this skill ships with a broader **first-wave preset bench** for operator convenience.

Rule:

- `canon` = repeatedly proven, held-across-reuse pack
- `preset` = callable default comparison pack that may still be provisional

## Built-in lens taxonomy

Every built-in lens must have a stable callable job before it enters the preset library.

- **Pape** = escalation trap / stage-of-reality
- **Marandi** = recognition threshold / sovereignty floor
- **Parsi** = settlement architecture / guarantee design
- **Freeman** = strategic backfire / diplomacy decay
- **Sachs** = enabling carrier / system-level exit
- **Macgregor** = force-feasibility collapse / coercive-fantasy failure
- **Ritter** = danger threshold / force constraint / military-professional warning
- **Diesen** = order transition / multipolar sequence / legitimacy shift
- **Davis** = practical room / bargaining geometry / end-state realism
- **Mercouris** = legitimacy fracture / imperial exhaustion / broken-settlement continuity
- **Mearsheimer** = structural incentive / bargaining-space / great-power realism
- **Wilkerson** = imperial-command decay / strategic overreach / elite-state critique

Taxonomy law:

- presets may only use lenses already declared here
- no lens enters the roster by prominence alone
- if a lens lacks a stable job, keep it out of the first-wave preset bench

## Roster-inclusion law

The preset bench is broad, but still governed.

- every built-in lens must appear in at least **one dual-lens or tri-lens preset**
- no preset may exist unless it owns a distinct question family
- orthogonality outranks symmetry
- breadth is mandatory, equal frequency is not

Maintenance check:

- when presets change, re-audit full roster coverage before adding more variants

## Workflow position

This skill is a **constitutional middle layer** in statecraft workflow.

It sits here:

`archive / routing -> multi-lens -> bridge / compact / lane draft / daily synthesis`

### Trigger this skill when

- the operator explicitly says `statecraft multi-lens`
- the operator asks for `dual lens`, `tri-lens`, or `compare these lenses`
- the object is already named
- the real uncertainty is explanatory responsibility rather than source truth
- the operator wants to know what the combined read changes beyond any one lens

### Do not trigger this skill when

- the job is source intake
- the job is raw month inventory
- the job is first-pass lane ownership resolution
- the job is direct drafting from one already-chosen lens
- the job is simple speaker routing without a real comparison problem

### Handoff surfaces

- `compact` for cross-lane mechanism notes
- `bridges` for durable lens doctrine or comparison notes
- owning lane surfaces for direct drafting
- `statecraft-daily-synthesis` when the result belongs in the daily shelf

## Fast chooser

Choose the preset by **dominant question family**, not by favorite speaker.

Use this ladder:

1. **Is the object mainly about threshold vs design?**
   - open **Marandi / Parsi**

2. **Is the object still visibly trapped, and does that trap change everything downstream?**
   - open **Pape / Marandi / Parsi**
   - if architecture is not yet real, step down to **Pape / Marandi**

3. **Is the object mainly about coercive-plan failure versus what room still remains?**
   - open **Macgregor / Davis**
   - if danger threshold itself is now active, step up to **Macgregor / Pape / Ritter**

4. **Is the object mainly about why escalation worsens leverage yet still keeps carrying politically?**
   - open **Freeman / Sachs**
   - if imperial or institutional decay is part of the object, step up to **Freeman / Sachs / Wilkerson**

5. **Is the object mainly about order transition, structural bargaining space, and what later architecture might become possible?**
   - open **Diesen / Mearsheimer / Parsi**

6. **Is the object mainly about what remains negotiable beneath a broken imperial or settlement carrier?**
   - open **Davis / Mercouris / Marandi**

Short operator law:

- choose the **smallest preset that still captures the decisive function**
- step **up** only when the third lens changes routing or diagnosis
- step **down** when one lens is only ambient background and is not changing the read

Current first-open defaults from live bench pressure:

- `Iran-war to deal transition` -> **Pape / Marandi / Parsi**
- `coercive plan collapse vs actual bargaining room` -> **Macgregor / Davis**
- `Hormuz escalation as imperial and order consequence` -> **Freeman / Sachs / Wilkerson**

## Built-in lens modes

### Dual-lens mode

Canonical pack:

- **Marandi** = recognition threshold / what must be acknowledged without humiliation
- **Parsi** = settlement architecture / what must be built so a bargain can carry

Use dual-lens mode when:

- trap logic is not the main uncertainty
- the object is mainly oscillating between threshold and design
- the operator wants to know whether the crisis is still below the recognition threshold or already an architecture problem

The canonical dual lens is best for answering:

- what must be recognized
- what must be built
- whether the object is still threshold-side or already architecture-side

#### First-wave dual-lens presets

Use these as preset packs when they clearly fit the object.

Design rule:

- each preset should own a distinct question family
- if two presets feel interchangeable, use the one with the cleaner question fit

1. **Marandi / Parsi** *(canonical dual lens)*
   - recognition threshold vs settlement architecture
   - best when the object is mainly `threshold vs design`

2. **Pape / Marandi**
   - escalation trap vs recognition threshold
   - best when the object is `are they still trapped` versus `has pressure already hardened the floor`

3. **Pape / Parsi**
   - moving escalation mechanism vs durable settlement contents
   - best when the operator needs `what is moving` versus `what a viable bargain must contain`

4. **Freeman / Sachs**
   - strategic backfire vs enabling carrier
   - best when the object is `why coercion is worsening leverage` versus `why the project continues anyway`

5. **Macgregor / Davis**
   - force-feasibility collapse vs practical-room realism
   - best when the object is `why the war cannot work` versus `what real bargaining room still exists`

Operator note:

- this is currently the cleanest non-canonical first-open preset for coercive-plan collapse objects

### Tri-lens mode

Canonical pack:

- **Pape** = escalation trap / why they cannot stop
- **Marandi** = recognition threshold / what must be admitted
- **Parsi** = settlement architecture / what must be built

Use tri-lens mode when:

- the object may still be inside ratchet logic
- architecture talk may be premature
- the stage-of-reality is itself contested

The canonical tri-lens does **not** replace the dual lens.

It is the dual lens **plus** a trap-stage diagnostic.

Do not force Pape into an object when the real question is only `recognition threshold vs settlement architecture`.

#### First-wave tri-lens presets

Use these as preset packs when they clearly fit the object.

Design rule:

- each preset should add a third lens that changes the object, not merely decorates it
- if the third lens does not alter routing or diagnosis, fall back to a dual-lens preset

1. **Pape / Marandi / Parsi** *(canonical tri-lens)*
   - escalation trap vs recognition threshold vs settlement architecture
   - best when stage-of-reality is itself contested

2. **Macgregor / Pape / Ritter**
   - force-feasibility collapse vs trap persistence vs danger threshold
   - best when the object is `why coercion cannot win`, `why the system still escalates`, and `where professional warning says the risk floor has moved`

3. **Freeman / Sachs / Wilkerson**
   - strategic backfire vs enabling carrier vs imperial-command decay
   - best when the object is `why escalation worsens leverage`, `why the project still carries`, and `what institutional decay it reveals`

4. **Diesen / Mearsheimer / Parsi**
   - order transition vs structural bargaining space vs settlement architecture
   - best when the object is `how a wider system is shifting`, `what structure permits`, and `what a durable bargain would still need`

5. **Davis / Mercouris / Marandi**
   - practical room vs legitimacy fracture vs recognition floor
   - best when the object is `what is still negotiable`, `what imperial or settlement failure has broken`, and `what the adversary will not accept beneath the floor`

Operator note:

- this remains a real bench preset, but it is still under-tested compared with the current first-open triads

## Preset review loop

Treat every preset as an **operational hypothesis**, not just a permanent convenience.

Review presets over time by asking:

- did this preset clearly fit the object?
- did another preset produce effectively the same read?
- did one lens do no real work?
- did the combined read change downstream routing?
- did the comparison yield something no single lens would have produced?

This review loop is doctrinal in v1. It does not require a logging system yet, but it must govern future refinement.

## Pack-promotion and negative pathways

Canonical packs remain rare.

Preset packs may become permanent canon only if they are:

- **repeatedly reusable** across more than one real object
- **non-redundant**, meaning the combined read adds something no single lens gives cleanly
- **role-stable**, meaning each lens keeps the same explanatory job across cases
- **routing-relevant**, meaning the pack changes retrieval, testing, or drafting decisions
- **held across reuse**, meaning the pack survives repeated proof runs, backtests, or operational use

Anti-promotion rules:

- do not promote by momentum
- do not promote by symmetry
- do not promote by elegance alone

Negative pathways:

- **merge** when two presets repeatedly answer the same question family
- **split** when one preset is trying to do two distinct jobs
- **rewrite** when the lenses are right but the described question family is wrong
- **demotion** when a preset is occasionally useful but not first-wave worthy
- **retirement** when a preset repeatedly fails to add unique value

Concrete criteria:

- demote when a preset repeatedly duplicates another preset's output
- merge when two presets consistently collapse into one question family
- retire when one lens repeatedly contributes no real explanatory work inside that preset
- rewrite when downstream routing is consistently different from what the preset claims

## Lightweight evidence expectations

Future refinement should treat these as meaningful signals:

- repeated operator selection of a preset
- repeated non-selection of a preset
- consistent downstream route after a given preset
- repeated need to override the claimed best-fit family
- repeated use of one lens mostly through other presets rather than through its nominal preset

Broad preset coverage improves operator reach, not proof of equal doctrinal maturity.

## Workflow

1. **Identify the shared object**
   - Name the live statecraft object in one line.

2. **Choose the right mode**
   - Use **dual-lens** for `recognition threshold vs architecture` or other clean two-function comparisons.
   - Use **tri-lens** when the object needs a third function to change routing or diagnosis.

3. **Classify each lens by explanatory role**
   - trap
   - threshold
   - architecture
   - legitimacy
   - carrier burden
   - bargaining consequence
   - continuity burden
   - order transition
   - practical room

4. **Separate each lens**
   - strongest contribution
   - what it misses
   - what it cannot carry alone

5. **State what becomes visible only in combination**
   - name the combined insight directly
   - avoid blended-summary prose

6. **Run one counterweight**
   - degradation read
   - falsifier
   - overreach test
   - wrong-stage warning

7. **Route only when the result clearly wants it**
   - bridge
   - compact
   - lane
   - daily synthesis

For **dual-lens** mode, the output should usually answer:

For **tri-lens** mode, the output should usually answer:
