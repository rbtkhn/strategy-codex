# Two-Channel Operator Architecture

work only; not Record.

## Purpose

This note defines the normal operator routing model for `strategy-codex`.

The repo has two primary operator **channels**:

- `singularity/` for acceleration, agency, substrate, control planes, recursive tooling, institutional redesign under technical pressure, and compounding experiments
- `statecraft/` for legitimacy, power, command, coercion, governance, settlement, and judgment-bearing geopolitical or civilizational objects

Other named lanes are normally **overlays, proving grounds, or execution surfaces** nested under one of those two channels rather than equal sovereign operator categories.

This is a routing law, not a filesystem migration law.

**Redesign map (path-tied):** [strategy-codex-redesign-brief.md](strategy-codex-redesign-brief.md) — ranked keep / refactor / freeze / externalize for this repo.

## Core Split

The shortest distinction is:

- `singularity` asks what system is emerging
- `statecraft` asks what object now has to be judged

Use that distinction first before reaching for older lane labels.

- **`fork revive` only:** explicit operator tokens may open museum merge archaeology (`--territory companion`, gate pipeline).

## Overlay Rule

An overlay may keep its own operating grammar without becoming an equal operator channel.

That means:

- `work-dev` may keep technical workflow discipline
- `work-cici` may keep cohort/advisor workflow discipline
- `work-business` may keep venture/accounting workflow discipline
- `statecraft` sublanes may keep lane-specific drafting grammar

But normal top-level routing should still begin by asking whether the work belongs to `singularity` or `statecraft`.

## Channel Crossings

Use [Singularity-Statecraft Handoff Law](./singularity-statecraft-handoff-law.md) when an object is hovering between the two channels.

The simple rule is:

- stay in `singularity` while the unresolved question is still system, architecture, protocol, substrate, or acceleration logic
- cross into `statecraft` when acceleration has become a legitimacy, authority, command, or settlement problem

## Guardrails

- Do not treat overlays as co-equal sovereign channels by default.
- Do not force every technical or commercial lane directly into `statecraft`; many remain singularity overlays.
- Do not pull Record or governed identity surfaces into this model.
- Do not use this note as a reason to rewrite lane-scope enforcement or move folders unless a later pass explicitly does that work.
