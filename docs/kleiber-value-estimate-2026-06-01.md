# Kleiber Value Estimate - 2026-06-01

work only; not Record.

This note records an estimate of the future efficiency gains and compounding value created by the recent Kleiber upgrades:

- interpretive-machine relocation into a clearer canonical singularity home
- prose-index centralization
- front-door thinning across `singularity` and `statecraft`
- explicit legacy redirect pattern

The point is not precision theater. The point is to preserve a falsifiable estimate that can later be compared against actual repo behavior.

## Short Estimate

These upgrades look like **high-compounding, medium-immediate-return** architecture work.

They are unlikely to feel as dramatic as a large new content tranche in the same day. But they should reduce several recurring costs that normally scale badly:

- placement hesitation
- duplicated doctrine drift
- front-door overload
- migration uncertainty

## Estimated Near-Term Efficiency Gains

Across the next few weeks of normal use, the likely gains are:

- **15-25% faster placement decisions** for new prose objects
- **20-35% less discussion overhead** around where a new prose object belongs
- **10-20% faster cold re-entry** into `singularity` and other prose-heavy front doors
- **meaningfully lower duplicate-edit risk** when routing doctrine changes again

These are not exact measurements. They are working estimates of reduced friction in ordinary operator flow.

## Why The Gains Should Compound

The strongest value here is not one-time cleanup. It is the improvement of the repo's **future change cost structure**.

The compounding mechanism looks like this:

1. one canonical chooser reduces parallel doctrine growth
2. thinner front doors reduce re-entry drag
3. explicit redirect law makes future migrations safer
4. safer migrations encourage cleaner canonical homes
5. cleaner canonical homes reduce future hesitation and drift

That loop should make later architecture changes cheaper than they would have been before.

## Highest-Value Compounding Channels

### 1. Reduced doctrinal drift

Now that [docs/prose-index.md](/C:/dev/strategy-codex/docs/prose-index.md) clearly owns prose-class routing, local shelf READMEs no longer need to act like rival taxonomy owners.

Expected result:

- fewer parallel definitions
- fewer subtle contradictions
- fewer multi-file cleanup passes when prose taxonomy shifts

### 2. Cheaper relocations

The interpretive-machine move plus [docs/legacy-redirect-pattern.md](/C:/dev/strategy-codex/docs/legacy-redirect-pattern.md) creates a reusable relocation grammar.

Expected result:

- future re-homing decisions happen faster
- old paths stay useful without staying ambiguous
- migrations stop feeling like bespoke doctrine surgery every time

### 3. Better front-door ergonomics

Thinner front doors reduce the cost of reopening a domain cold.

Expected result:

- less scroll burden
- fewer mixed-role READMEs
- faster recovery of the actual next move

### 4. Better local/global distinction

The repo now has a clearer split between:

- shared law
- local shelf flavor
- compatibility residue

Expected result:

- more stable canonical owners
- less accidental duplication
- lower temptation to restate a law everywhere

### 5. Higher-yield future Kleiber passes

Because the pattern is now explicit, future simplification work should get easier to identify and cheaper to execute.

Expected result:

- more one-move, repo-wide simplifications
- fewer broad cleanup projects
- better elegance-to-effort ratio

## Where The Value Should Appear First

These gains should show up most clearly when:

- creating new `notes/` or `essays/` shelves
- deciding whether something belongs in `synthesis/`, `notes/`, `essays/`, or doctrine
- relocating material out of old `work-*` compatibility lanes
- cleaning overloaded READMEs
- reopening `singularity` or `statecraft` from a cold start

## Best Working Judgment

If the repo keeps expanding at anything like its current pace, these Kleiber passes may end up being **more valuable than several larger content additions**, because they improve the terms on which future work is done.

The best concise judgment is:

```text
the immediate gain is moderate,
the monthly compounding value is high,
and the architectural value is very high
because future clean change should become cheaper
```

## Signals To Watch

If the estimate is correct, the following should become true:

- fewer conversations stall on placement questions
- fewer READMEs need to be edited together to change one routing rule
- future relocations require fewer explanatory patches
- local shelf READMEs get shorter and more stable over time
- new prose shelves emerge with less hesitation and less doctrinal duplication

## Falsifiers

The estimate is too optimistic if:

- local READMEs quickly re-expand into rival taxonomy owners
- prose-class uncertainty remains just as high as before
- relocations still feel bespoke and high-friction
- front doors become overloaded again within a short cycle
- operators still need repeated clarification to distinguish `synthesis/`, `note`, `essay`, and doctrine
