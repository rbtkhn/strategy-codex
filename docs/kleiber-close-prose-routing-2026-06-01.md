## What Changed

- [docs/prose-index.md](/C:/dev/strategy-codex/docs/prose-index.md) now clearly owns prose-class routing.

- [docs/prose-cluster-placement-comparison.md](/C:/dev/strategy-codex/docs/prose-cluster-placement-comparison.md) now gives one small live test for how the same cluster should behave differently in `essays/`, `notes/`, and `docs/skill-work/`

## The Real Lesson

The repo did not need more taxonomy. It needed one canonical chooser and thinner local front doors.

That is the key Kleiber lesson here:

```text
centralize the class law
decentralize the shelf flavor
```

When local READMEs start restating the whole prose theory, drift becomes likely. When they instead assume the class choice has already been made, the repo gets faster and cleaner.

## What This Clarified

- `essays/` should own transportable arguments
- `notes/` should own bounded promoted objects
- `synthesis/` should remain an extraction layer rather than trying to become a general prose shelf
- `docs/skill-work/` should hold operator doctrine, procedure, or compatibility residue, not hidden canonical prose ownership

## Best Future Test

If a future object is hard to place, ask:

1. is it helping the operator work or preserve compatibility?
2. is it a bounded reusable seam?
3. is it now a stand-alone thesis?

If the answer is still fuzzy after those three questions, the object is probably not ready for promotion.

## Elegant Next Wedge

If prose routing drifts again, the next honest move is not to add more taxonomy prose. It is to find the local shelf that is re-expanding into a second canonical chooser and thin it back down.
