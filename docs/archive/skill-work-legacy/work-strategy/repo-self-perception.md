# repo self-perception

This note names a recurring maintenance problem in strategy-codex:

the repo often acquires reality faster than it re-describes reality.

That lag can make the corpus look thinner, less formed, or less reusable than it really is.

More deeply, it means a notebook can be **truer in substance than in self-perception**.

That is not just a cataloging issue.
It is a truth condition for later judgment.

## The three layers

The repo has at least three different truth layers:

1. **capture reality**  
   What is actually on disk.

2. **representation reality**  
   What inventories, ledgers, arc notes, and routing surfaces say exists.

3. **perceived completeness**  
   What an operator or later pass feels the repo contains.

Those layers can diverge.

That divergence is not trivial bookkeeping.
It changes judgment.

A notebook that under-sees itself will ask smaller questions than its own holdings can already support.

## The recurring weakness

The characteristic failure is often not simple absence.

It is **recognition latency**:

- the repo captures more than it knows it has
- it knows more than its inventories show
- it has patterns before it has names for those patterns

So a maintenance pass should not ask only:

- what is missing?

It should also ask:

- what is already here but still under-seen?

## Three common failure modes

### 1. Extent failure

The repo has more of a lane, series, or family than the visible ledger admits.

Example shape:

- multiple captures exist
- inventory still implies a thinner corpus

### 2. Form failure

The repo has a real pattern, but has not yet named the pattern as an object.

Example shape:

- repeated host × guest run exists
- no `speaker arc` yet

or:

- recurring mixed-source seam exists
- no packet family or doctrine yet

### 3. Routing failure

The repo has the material and maybe the pattern, but not the right re-entry surface.

Example shape:

- useful object exists
- operator cannot find it quickly
- rediscovery happens by search rather than by designed routing

## Absent, partial, unrecognized

These should stay sharply separated.

- **absent corpus** = the material is not actually there
- **partial corpus** = some of the material is there, but the series is incomplete
- **unrecognized corpus** = the material is there, but the repo does not yet describe it honestly or usefully

These are different conditions and need different repairs.

They also produce different kinds of false feeling:

- absent corpus produces justified uncertainty
- partial corpus produces bounded uncertainty
- unrecognized corpus produces unnecessary uncertainty

## Why this matters

If the repo misreads unrecognized corpus as absent corpus, it may:

- duplicate work
- understate a lane's maturity
- delay useful synthesis
- ask weaker questions than the corpus already supports

In that sense, self-perception is part of strategy quality.

The notebook is not only judged by what it contains.
It is also judged by how truthfully it sees what it contains.

A repo can therefore fail not by lacking material, but by **mis-seeing its own maturity**.

## Maintenance rule

When a pass reveals new useful structure, ask four questions:

1. is the material actually captured?
2. do the visible ledgers represent it?
3. has the pattern been named at the right level?
4. can a later operator re-enter it without rediscovery?

If the answer to `1` is yes but the others lag, the likely problem is not missing corpus.
It is repo self-perception lag.

## Current lesson

The `yt-dlp` / Baud audit is one example, not the whole doctrine.

The same pattern appeared in:

- packet work
- speaker-arc recognition
- inventory reconciliation

So `inventory failure` should be read as one operational subtype of a broader truth:

**strategy-codex can be richer than its self-description, and maintenance work often consists in helping the repo perceive itself more accurately.**
