# Singularity-Academy First-Wave Send Checklist

non-authoritative. This is an operator execution sheet, not proof of demand.

## Purpose

Use this checklist before sending the first real outreach messages for the AI Operating System Sprint.

The goal is not perfect copy.
The goal is to make sure the first wave is specific, honest, and logged.

## Use rule

Use this with:

- [Singularity-Academy Top 3 Outreach Drafts - 2026-05](singularity-academy-top3-outreach-drafts-2026-05.md)
- [Singularity-Academy Sprint Prospect Pipeline](singularity-academy-sprint-prospect-pipeline.md)
- [Singularity-Academy First-Wave Outreach Log](singularity-academy-first-wave-outreach-log.md)

Do not send if the note still sounds like generic AI consulting.

## Pre-send checks

Before sending, confirm all `7`:

1. the prospect is already in the pipeline
2. the message names one workflow pain only
3. the first sentence is personalized to a current public surface
4. the ask is one bounded next step only
5. the copy does not claim market proof you do not have
6. the likely package is visible internally
7. the follow-up date is chosen before the send

## Personalization rule

Change at least these fields before sending:

- subject line if needed
- first sentence
- one phrase naming the workflow pain
- contact route

If those changes are not obvious, the prospect is still too vague.

## Send format

For each send, capture:

- date sent
- prospect
- channel
- version used
- personalization anchor
- ask made
- planned follow-up date

Record it here:

- [Singularity-Academy First-Wave Outreach Log](singularity-academy-first-wave-outreach-log.md)

Update the pipeline stage from `idea` to `sent` on the same day.

## Send sequence

### Pass 1 - Final reality check

- re-read the target's latest public page
- confirm the workflow pain is still plausible
- remove any line that sounds more visionary than useful

### Pass 2 - Send

- send one note
- do not send multiple variants to the same target
- keep the ask to a one-page packet or a short call

### Pass 3 - Log

- add the send to the outreach log
- update the pipeline row
- choose the follow-up date now, not later

## Follow-up timing

Default:

- first follow-up after `4-6` business days

Do not follow up if:

- the first note was obviously underpersonalized
- the target has publicly shifted away from the use case
- the pipeline should rerank them out of the first wave

## Stop signals

Do not send yet if:

- the message explains `singularity-academy` before naming workflow pain
- the workflow pain cannot be named in one sentence
- the likely buyer still sounds like enterprise procurement
- you are tempted to promise results you cannot receipt

## Success signal

The send is good enough if a serious prospect could answer one of these:

- `send the one-pager`
- `tell me more about the workflow`
- `yes, let's take the short call`
