# Kleiber Close - Routing And Redirects - 2026-06-01


This close records the deeper pattern made visible by the recent Kleiber passes.

## What Became Clear

The repo gets cleaner not when every local surface explains itself more fully, but when:

- one canonical surface owns the law
- local shelves keep only the flavor they uniquely need
- legacy paths preserve access without preserving ambiguity

That is the real thread connecting:

- the interpretive-machine relocation
- the prose-index centralization
- the thinning of singularity and statecraft front doors
- the new legacy redirect pattern

## When To Centralize Law

Centralize when:

- several local READMEs are beginning to restate the same classification rule
- a routing decision should not vary by shelf
- different surfaces are starting to look like rival owners of the same concept

The right home is usually one compact canonical chooser, not a thicker set of parallel explanations.

## When To Thin Local Surfaces

Thin local surfaces when:

- the class decision has already been made elsewhere
- the local README is repeating shared doctrine instead of adding local orientation
- the front door is trying to be both an entry surface and a ledger

A good local surface should mostly answer:

- what lives here
- what is the local version of the shared class
- where do I go next

## When To Relocate Instead Of Restate

Relocate when:

- a concept now has a natural canonical home in a live domain
- the old home would otherwise keep pretending to own the doctrine
- the new home can carry the object more honestly than the old lane can

Do not merely restate the same doctrine in both places. Move the owner, then degrade the old path into a redirect or compatibility shell.

## Best Compression

Use this as the working rule:

```text
centralize shared law
thin local front doors
relocate real owners
degrade old paths into honest redirects
```

## Elegant Next Test

If a future shelf feels heavy, ask:

1. is this surface carrying shared law it no longer needs to own?
2. is this surface mixing front-door role and ledger role?
3. is there already a more honest canonical home elsewhere?

If yes, the next Kleiber move is probably not a new framework. It is a simplification.
