# cici-ai Public GitHub Coordination Pattern

**Status:** WORK / coordination pattern
**Scope:** beginner-friendly public-repo workflow for cici-ai team members
**Boundary:** This pattern uses public GitHub repos as the shared memory layer. It does not require a separate login app.

## Purpose

Use public GitHub activity as the team’s shared source of progress, memory, and accountability.

This pattern is useful when the goal is:

- visible progress
- simple onboarding
- low friction for beginners
- one place to monitor work across the cohort

## What public GitHub replaces

- scattered chat updates
- private note silos
- extra login steps for basic coordination

## What each member does

Each person keeps a small, consistent set of files in their own OB1 repo:

- `docs/personal/daily-journal/YYYY-MM-DD.md`
- any repo notes or proof artifacts for first tasks
- optional screenshots or links when something important changes

## Daily loop

1. Write rough notes during the day.
2. Turn them into a short daily journal entry.
3. Review the entry yourself.
4. Commit and push it to GitHub.
5. Let the team read the repo history instead of asking for repeated status updates.

## Team monitoring loop

The operator or any teammate can review public GitHub activity by checking:

- commits
- issues
- pull requests
- daily journal files
- proof packets or task artifacts

This makes progress visible without needing a private app for the basic coordination layer.

## Recommended beginner structure

Use the same headings every day:

- what I worked on
- what changed
- what is blocked
- what I plan to do next
- evidence or notes

## When this is enough

This is enough when the team only needs:

- shared visibility
- daily accountability
- lightweight coaching
- public proof of movement

## When a private app may still help

If the team later wants:

- private credentials
- gated access
- a centralized UI
- token-based features

then a private app can sit on top of the public repo pattern. But it is not required for the basic shared-memory objective.

## Bottom line

For a beginner team, public GitHub plus a standard daily journal is the simplest way to create a shared memory loop.
