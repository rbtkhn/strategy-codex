# Singularity-Academy Mock Prospect Progression - AI Adjacent

WORK only. This is a rehearsal surface, not real market traction.

## Purpose

Show what the first real prospect movement should look like from:

- `sent`
- `reply`
- `packet`
- `call`
- `proposal`

without polluting the live pipeline or outreach log with invented demand.

## Why AI Adjacent is the best rehearsal

AI Adjacent is the cleanest first-wave fit because its public architecture already names:

- AI-first editorial flow
- human final review
- git-backed artifact logic

That means the mock can stay close to the actual offer instead of compensating with heavy explanation.

## Stage 1 - First send

### Prospect

- AI Adjacent
- archetype: research / content
- likely package: `$2,500` base sprint

### Message used

Use:

- [Singularity-Academy Top 3 Outreach Drafts - 2026-05](singularity-academy-top3-outreach-drafts-2026-05.md)

Likely first line:

`I came across AI Adjacent's About page and was struck by how close your public architecture is to a problem I've been working on from the opposite direction.`

### Ask

- send the one-page packet if useful

### Good outcome

- they reply with curiosity tied to workflow, not just topic

### Bad outcome

- they treat it as generic AI consulting

## Stage 2 - Meaningful reply

### Plausible reply

```text
Interesting. We do have a fairly explicit pipeline already, but there may still be some hidden review burden between draft generation and final publication. Happy to see the short version.
```

### Classification

- type: `ask for the one-pager`
- quality: good
- reason: the reply names the workflow shape and requests the next artifact

### Next move

Send:

- [Singularity-Academy Sprint One-Page Packet](singularity-academy-sprint-one-page-packet.md)
- [Singularity-Academy Sprint FAQ](singularity-academy-sprint-faq.md)
- [Singularity-Academy Target Packet - AI Adjacent - 2026-05](singularity-academy-target-packet-ai-adjacent-2026-05.md)

## Stage 3 - Packet follow-up

### Cover note

Use:

- [Singularity-Academy Sprint Proposal Cover Notes](singularity-academy-sprint-proposal-cover-notes.md)

Adapted packet follow-up:

```text
Thanks. Sending the short packet plus a tighter note on why I thought AI Adjacent might be a fit.

If the shape feels close, the best next step is a short workflow call. The point of that call would be to identify whether there is one recurring editorial workflow where trust or review is still doing too much invisible work.
```

### Good outcome

- they answer with one workflow pain
- or they accept a short call

## Stage 4 - Workflow call

### Most likely workflow named

- AI-assisted editorial draft -> final reviewed publishable artifact

### Most likely pain named

- the public pipeline exists, but someone senior still carries hidden trust work between draft generation and final judgment

### Filled call summary

- workflow named: AI-assisted editorial draft to final reviewed artifact
- current pain: hidden review and trust burden after generation
- AI already in use: yes, strongly
- main authority blur: what is draft-ready versus publishable without senior rescue
- fit score: `5`
- package likely: `$2,500` base sprint
- next step: proposal

### Likely objection

- `we already have a pipeline`

### Best response

The sprint is not for teams lacking a pipeline.
It is for teams where the visible pipeline still depends on invisible trust work that has not yet been made inspectable or reusable.

## Stage 5 - Proposal handoff

### Best proposal to adapt

Use:

- [AI Operating System Sprint Proposal - Sample Research / Content Team](singularity-academy-sprint-sample-proposal-research-content.md)

### Minimal changes needed

Replace:

- organization
- owner
- exact workflow wording
- current pain lines
- start window

Keep mostly intact:

- package
- method
- success criteria
- boundary language

### Proposal cover note

Use:

- [Singularity-Academy Sprint Proposal Cover Notes](singularity-academy-sprint-proposal-cover-notes.md)

Strong-fit handoff:

```text
Thanks again for the call.

I think there is a real fit here because the workflow is concrete, the trust and review burden are visible, and the scope is small enough to handle as a bounded sprint.

I am sending a short proposal next with the workflow in scope, the package, and the success criteria. If the scope looks right, we can confirm the package and start window from there.
```

## Mock stage summary

| Stage | Artifact to use | Success signal |
|-------|-----------------|----------------|
| `sent` | Top 3 outreach draft | prospect asks for more |
| `reply` | first-response handling | workflow-shaped curiosity |
| `packet` | one-page packet + FAQ + target note | short call accepted or workflow named |
| `call` | discovery call + worksheet | one workflow clearly in scope |
| `proposal` | sample research/content proposal | package and start window are the only open questions |

## What this rehearsal proves

- the repo can support a full first-sale chain without starting from blank pages
- the offer can stay narrow through each stage
- the first real buyer interaction can be mirrored with low operator friction

## What this rehearsal does not prove

- that AI Adjacent will reply
- that any buyer will pay
- that the `$2,500` package will close in practice
