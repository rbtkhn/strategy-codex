# Singularity-Academy First-Wave Outreach Log

WORK only. This is an operator movement log, not proof of demand.

## Purpose

Capture what was actually sent in the first outreach wave so the sprint can learn from real contact instead of memory blur.

Use this alongside the live stage sheet:

- [Singularity-Academy Sprint Prospect Pipeline](singularity-academy-sprint-prospect-pipeline.md)

## Logging rule

One row per real send or meaningful reply.

If nothing was sent, do not backfill theater.

## Event types

- `send-1` = first outreach sent
- `send-2` = follow-up sent
- `reply` = meaningful reply received
- `packet` = one-page page or proof packet sent
- `call-booked` = workflow call scheduled
- `proposal-sent` = proposal sent
- `parked` = intentionally paused
- `lost` = explicitly not moving

## Minimum row quality

Do not leave the row vague.

At minimum, each row should let you answer:

- what exactly happened
- what the target responded to
- what happens next

## Weekly readout

At the end of the week, answer:

1. how many first sends went out?
2. how many meaningful replies came back?
3. which personalization anchor got the clearest response?
4. which objection repeated?
5. which prospect moved closest to a call?

Add stage truth to:

- [Singularity-Academy Sprint Prospect Pipeline](singularity-academy-sprint-prospect-pipeline.md)

## Failure signal

If the log starts to fill with sends but no reply quality improves, the problem is probably the offer framing or prospect fit, not just volume.
