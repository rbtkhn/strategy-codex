# Singularity-Academy Sprint Outreach Sequence

non-authoritative. Draft outreach copy.

## Use

Use this after the sales page and proof packet exist.

Goal:

- get a close-fit prospect onto one bounded workflow call

Do not use this as mass cold outreach.

## Prospect filters

Best prospects:

- already using AI weekly or daily
- visibly experiencing workflow or reporting sprawl
- able to approve a small paid sprint
- close enough to trust a narrow experiment

## Message 1 - Workflow pain

Subject:

`Quick idea for your AI workflow`

Body:

```text
I have been building a small 30-day AI operating system sprint for teams that are already using AI but still doing the hard part invisibly.

The focus is narrow: one recurring workflow, one reporting layer, one review/receipt contract, and clearer boundaries around what AI may do versus what still needs human approval.

I thought of you because {specific workflow pain or team context}.

If useful, I can send a one-page version and we can see whether there is a real fit.
```

## Message 2 - Offer clarity

Send if they respond with curiosity but not commitment.

```text
The sprint is not generic AI consulting.

It is a bounded install:
- one live workflow
- one daily or weekly brief
- one proof/review layer
- one handoff playbook

The point is to make the workflow easier to trust and reuse, not just more automated.

If you want, I can send the short package and you can tell me whether the workflow is real enough to be worth a call.
```

## Message 3 - Direct call ask

Send after the page or packet is shared.

```text
If the shape looks close, the next step is a 30-minute workflow call.

That call is only for three questions:
1. what recurring workflow matters most
2. where authority is currently blurry
3. whether a `$2,500` base sprint or `$5,000` proof-loop sprint is the better fit

If the workflow is not real enough, we should know quickly.
```

## Objection handling

### "We already use AI heavily."

Good. The sprint is for teams with AI activity but weak review and routing, not teams starting from zero.

### "We need software, not consulting."

This is a fast install and proof loop first. If the workflow proves stable, software or deeper automation can be decided from evidence instead of theory.

### "We need autonomy."

The sprint is designed for teams that want leverage without giving up review. It is a poor fit for buyers seeking silent automation.

### "We are too early."

That may be true. The best fit is a workflow painful enough that a 30-day install could make a visible difference.

## Outreach discipline

- personalize the first sentence
- name one real workflow pain
- do not lead with futurism
- do not overclaim external proof
- keep the ask to one bounded call
