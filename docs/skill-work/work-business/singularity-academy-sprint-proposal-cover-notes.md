# Singularity-Academy Sprint Proposal Cover Notes

WORK only. Reusable short notes for sending the next step after a call or packet review.

## Purpose

Reduce friction between:

- packet -> call
- call -> proposal
- proposal -> confirmation

Use these as short cover notes, not as full sales letters.

## 1. Packet follow-up -> short call

Use when the prospect has seen the packet and there is real curiosity but the workflow is not fully named yet.

```text
Thanks for taking a look.

If the shape feels close, the best next step is a short workflow call. The goal of that call is simple: name the one recurring workflow that matters most, identify where trust or review is still blurry, and decide quickly whether the `$2,500` or `$5,000` version is the right fit.

If that sounds useful, send me two times that work.
```

## 2. Strong-fit call -> proposal

Use when the call clearly surfaced one real workflow.

```text
Thanks again for the call.

I think there is a real fit here because the workflow is concrete, the trust and review burden are visible, and the scope is small enough to handle as a bounded sprint.

I am sending a short proposal next with the workflow in scope, the package, and the success criteria. If the scope looks right, we can confirm the package and start window from there.
```

## 3. Partial-fit call -> narrowed follow-up

Use when the pain is real but the workflow is still too broad.

```text
Thanks again.

I think the pain is real, but the scope is still slightly too broad for a clean sprint proposal. The most useful next step is to isolate one first workflow rather than try to fix the whole operating system at once.

If you want, I can send back one narrowed workflow recommendation and we can decide from there whether the sprint still makes sense.
```

## 4. Proposal sent -> confirmation ask

Use when the written proposal has been delivered.

```text
Proposal attached.

The key things to confirm are:

1. the workflow in scope
2. the package
3. the start window

If those three are right, the sprint is ready to move.
```

## 5. Parked for later

Use when the fit is plausible but timing is wrong.

```text
Thanks for the clarity.

I agree this only makes sense when the workflow pain is strong enough that a `30`-day intervention would matter. I will treat this as parked rather than try to force a fit too early.

If the workflow becomes more urgent later, I would be happy to reconnect.
```

## Use rule

- keep the note shorter than the packet or proposal itself
- use the prospect's own workflow language when possible
- do not restate the whole philosophy
- do not force urgency that is not there
