# Conductor recursive-improvement benchmark


**Purpose:** Quantify whether the combination of named **conductor stances** and the **four-movement arc** is increasing Strategy-codex's recursive self-improvement power over time.

This benchmark does **not** measure geopolitical truth. It measures whether conductor passes are improving the repo's ability to improve its own **judgment machinery**, **method surfaces**, and **durable re-entry paths**.

## Core claim under test

The hypothesis is not merely:

- conductor passes feel better

The hypothesis is:

- named conductors improve **selection pressure**
- the four-movement arc improves **completion pressure**
- together they increase the rate at which insight becomes:
  - a durable object
  - a reusable method
  - a generalized pattern
  - a better future starting point

## Unit of analysis

One unit is a **closed conductor arc**:

1. named conductor invoked
2. action menu emitted
3. operator selects one or more movements in sequence
4. pass reaches a real **D / Finale** close

Orientation-only turns do **not** count as benchmark units unless they later close as a full arc.

## What counts as recursive lift

The benchmark treats recursive lift as the combined ability to do four things:

1. choose better next moves
2. finish those moves as real sequences rather than isolated insights
3. convert insights into durable repo form
4. leave behind better re-entry conditions for future work

## V1 scorecard

Score each dimension from **1** to **5** for a review window such as 7 days, 30 days, or one named wave.

| Dimension | 5 | 3 | 1 |
|---|---|---|---|
| **Arc closure rate** | Most named conductor passes close as real `A→D` arcs | Mixed: several closes, several stalls | Many conductor turns remain orientation-only or die mid-arc |
| **Durable artifact yield** | Arcs regularly produce notes, pages, skills, docs, or shelf wiring | Some durable outputs, some chat-only insight | Most value stays in the thread and does not land on disk |
| **Method conversion rate** | Many arcs turn local insight into a reusable procedure, doctrine, rubric, or skill | Occasional methodization | Almost all arcs remain one-off problem solving |
| **Generalization rate** | New methods are stress-tested on fresh seams or new domains | Some second-case testing | Insights stay trapped in founding examples |
| **Re-entry clarity** | The work leaves explicit entrypoints, crosswalks, or hierarchy for future operators | Some usable paths, some hidden tribal memory | Re-entry depends on remembering the whole conversation |
| **Publish completion** | Work is not only committed but successfully shipped or clearly publication-ready | Usually committed, sometimes blocked from publish | Repeated local residue with no clean publication line |

## Optional quantitative helpers

These are simple, imperfect proxies. Use them to support judgment, not replace it.

### 1. Arc closure rate

`closed_arcs / initiated_arcs`

- initiated arc = conductor name invoked and action menu emitted
- closed arc = a real `D / Finale` outcome reached

### 2. Durable artifact yield

`durable_artifacts_created_or_materially_revised / closed_arcs`

Count examples like:

- new pages
- source-hygiene notes
- speaker arcs
- doctrine notes
- crosswalks
- skills
- README entrypoint changes

Do **not** count ephemeral commentary or raw command output.

### 3. Method conversion rate

`closed_arcs_that_produced_a_reusable_method_surface / closed_arcs`

Reusable method surfaces include:

- skills
- recipes
- doctrine notes
- benchmark specs
- chooser notes
- templates

### 4. Generalization rate

`closed_arcs_with_explicit_second-domain_or_cold-seam_test / closed_arcs`

This is the anti-self-congratulation measure. A method only scores here if it survives a different seam, lane, or evidence texture.

### 5. Re-entry clarity rate

`closed_arcs_that_left_an_explicit_reentry_path / closed_arcs`

Examples:

- "best re-entry point" stated in a README
- crosswalk added
- speaker arc cited from lattice/thread surfaces
- router note for half-remembered future operator

### 6. Publish completion rate

`successfully_pushed_closes / closed_arcs`

If a push is blocked by external auth rather than repo quality, note that separately instead of silently scoring the work as weak.

## V1 composite index

Use a simple weighted index for month-to-month comparison:

`recursive_lift_index = 0.20*closure + 0.20*durable + 0.20*method + 0.15*generalization + 0.15*reentry + 0.10*publish`

Where each input is normalized to `0.0–1.0`.

This index is only a guide. The actual journal should still explain **why** a score moved.

## Review rhythm

Recommended windows:

- **7-day:** did the last cluster of conductor passes actually land?
- **30-day:** are we compounding or just producing many clever closes?
- **quarterly:** did the repo gain new reusable judgment machinery?

## Minimal benchmark questions

At each review, answer:

1. Did conductor passes produce more than good chat?
2. Did the four-movement arc convert more passes into durable closes?
3. Did local insight become reusable method?
4. Did the methods survive fresh seams?
5. Is future re-entry getting easier?

If the answer to `3–5` is repeatedly yes, recursive lift is probably real.

## Current working hypothesis

The strongest current expectation is:

- **named conductors** improved **discrimination**
- the **four-movement arc** improved **follow-through**
- together they sharply increased the rate of:
  - methodization
  - stress-testing
  - explicit re-entry design

That is exactly the claim the journal should keep testing rather than assuming.
