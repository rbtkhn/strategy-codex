# Speaker Arc vs Canon Note

WORK only; not Record.

This note explains why **speaker arc** is the better term than **canon note** for the host × guest notebook object.

The difference is not only semantic. It is also:

- aesthetic
- operational
- philosophical

## Short answer

`speaker arc` is better because it names a **recurring conversational contour**.

`canon note` named the object as if it were primarily:

- classificatory
- finished
- externally judged

But that is not what these notebook objects are doing.

They are doing something more alive:

- recognizing repeated shape
- preserving a reusable entry path
- compressing a host × guest run without pretending it is complete

## Semantic difference

`canon note` emphasizes:

- selection
- authority
- admission
- closure

`speaker arc` emphasizes:

- recurrence
- contour
- development
- partial unity

That is a better semantic fit for a repeated interview lane that is useful before it is final.

## Aesthetic difference

`canon note` sounds:

- rigid
- finished
- shelf-like
- a little external to the living stream

`speaker arc` sounds:

- temporal
- relational
- dynamic
- native to the stream itself

That matters because the notebook should sound like it understands living material, not only how to classify it after the fact.

## Operational difference

The two names also guide different operator behavior.

`canon note` quietly encourages:

- thinking the lane is settled
- overrating closure
- treating the object as a mini-shelf
- focusing on admission rather than reuse

`speaker arc` encourages:

- asking why the recurring run matters
- naming the strongest entry points
- preserving boundaries
- treating the object as compact routing help

That makes it a better working term.

## Philosophical difference

The deeper issue is what kind of object the notebook is trying to preserve.

These host × guest notes are usually:

- more than a set of episodes
- less than a complete worldview
- dependent on repeated conversation
- still open to further movement

`canon note` pushes them too early toward finished authority.

`speaker arc` lets them stay what they really are:

- partial
- recurring
- legible
- still alive

## Why the older term was still understandable

`canon note` was not nonsense.

It captured something real:

- there is selection
- there is ranking
- there is a recommended entry point

So the old term was understandable as a first approximation.

But once the notebook had enough examples, the costs became clearer:

- it over-signaled closure
- it under-signaled conversation
- it made the object feel too static

That is why the rename was worth making.

## Practical rule

Prefer **speaker arc** when the object is:

- a recurring host × guest lane
- stream-local
- interpretive
- compact
- open to further accumulation

Keep **canon** language only where you truly mean:

- corpus admission
- fixed reading list
- settled authority
- stronger closure than this notebook object usually has

## Bottom line

`speaker arc` is better than `canon note` because it names the object by its living shape rather than by a prematurely finished status.
