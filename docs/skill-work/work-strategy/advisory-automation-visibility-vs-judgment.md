# Advisory Automation: Visibility vs Judgment

This automation begins by specifying the visibility it is meant to create. Its first purpose is to make the field more truthfully legible: what is present, what is absent, what is hidden, and what remains unresolved. The structures that follow exist to preserve that clearer encounter, expose the repair path, and support later judgment without prematurely substituting for it.

## Core law

In advisory automation, illuminate the field first, make repair legible second, and attempt judgment substitution last, if at all.

## Why this distinction matters

`Automation` is too coarse a category for work-strategy.

Some tools primarily improve what the operator can **see**. Others start to influence what the operator will **conclude**. Those are different maturity classes with different risks.

Without this distinction:

- measurement can silently become authority
- a queue can start to feel like the field itself
- a ranking can be mistaken for a judgment the operator no longer needs to make

## Maturity class 1: visibility automation

Visibility automation exists to:

- reveal the field more truthfully
- preserve provenance
- expose gaps
- make repair legible
- improve operator encounter without displacing operator judgment

Typical outputs:

- receipts
- ledgers
- summary states
- gap reports
- repair queues

Failure mode:

- under-seeing, misreporting, or flattening the field

Success condition:

- the operator can tell what is present, absent, hidden, and unresolved more clearly than before

## Maturity class 2: judgment automation

Judgment automation exists to:

- rank significance
- infer meaning
- prioritize interpretations
- recommend conclusions
- partially substitute for evaluative work

Typical outputs:

- strong prioritization of what matters most
- automatic narrative weighting
- recommendation layers that tell the operator what to think next

Failure mode:

- overreach, false confidence, and silent distortion of interpretation

Success condition:

- judgment assistance is genuinely earned by the evidence base and remains legible enough to audit

## Proper sequence

The right sequence is:

1. make the field visible
2. shape how the field is encountered
3. expose the repair path
4. only then deepen judgment

This sequence appeared clearly in two recent work-strategy arcs:

- the cognition-streams audit layer
- the Predictive History CIV-MEM transfer package

In both cases, the strong move was not to automate conclusion first. It was to improve first contact with the object.

## Practical rule

When drafting a new advisory-automation spec, begin by answering:

- what field is being made more visible?
- what kind of distortion or invisibility exists now?
- what repair path should become legible?
- what judgment, if any, should remain explicitly human?

If those answers are weak, the automation is probably reaching for judgment too early.
