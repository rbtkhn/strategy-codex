# Packet-before-synthesis doctrine

WORK only; not Record.

**Purpose:** This note captures the slower strategist tempo behind source-hygiene packets. Use it when a live seam is strategically valuable but still too mixed, dual-register, or rhetorically unstable to compose directly into `days.md`, a weave, or a stronger notebook judgment.

This note does **not** restate packet sections or file shape. The operational recipe lives in [source-hygiene-packets.md](source-hygiene-packets.md). This note exists to explain *when* packet work should come first and *how* mixed seams should mature before synthesis.

## Core claim

Not every good source should become judgment immediately.

Some sources should first become **disciplined potential**:

- preserved
- attributed
- tiered
- held open until the seam matures

That is what packet work is for.

## When packet work should precede synthesis

Choose a packet before synthesis when one or more of these conditions hold:

1. the seam is analytically strong but fact-tier mixed
2. the seam contains more than one evidence layer with different jobs
3. the rhetoric is itself informative, but should not be laundered into event-fact
4. the notebook would become flatter or more certain if forced into one sentence too early

This is not indecision. It is anti-flattening discipline.

## Three reuse modes

The current packet family implies three different kinds of strategist reuse:

- **mechanism reuse**: a source helps explain what a conflict is structurally doing
- **process reuse**: a source helps name sequencing, bargaining, or diplomatic shape
- **register reuse**: a source reveals red lines, legitimacy language, or political imagination

Each mode can be valuable before the seam is fully pinned. The important thing is to say which mode is doing the work.

## Dual-register maturity rule

When a seam contains both an **official-primary line** and a **commentator gloss**, do not collapse them on day one.

Use this maturity sequence instead:

1. **Official-primary wording**  
   Preserve the declarative state line as its own object.
2. **Attributed gloss**  
   Preserve the commentator or interpreter restriction as a second layer, not as “what the state said.”
3. **Institutional corroboration or divergence**  
   Wait for a second official, institutional, operational, or field receipt that either narrows the gap or shows the gap widening.
4. **Only then synthesize**  
   Until that point, preserve the gap itself as part of the truth of the seam.

## Example: Araghchi / Marandi

The April 2026 Hormuz seam is the clearest working example.

- **Araghchi** gives the official foreign-minister register: commercial passage named as open on a PMO-coordinated route during the ceasefire window.
- **Marandi** gives the English-register gloss: “open” is not unrestricted; Iran decides; designated route; Lebanon/Hormuz pressure language.

These are not the same object.

The notebook should not compress them into one line such as:

- “Iran says Hormuz is open”
- or “Iran says Hormuz is conditional”

Both are too flat if they erase the layered structure.

The better rule is:

- official line = posture
- gloss = interpretive restriction
- later institutional echo or divergence = maturity test
- only then = notebook-safe synthesis

## What packet work protects

Packet work protects the notebook from four common failures:

1. **tier confusion**: commentary hardened into fact
2. **voice collapse**: distinct institutional or rhetorical registers merged into one “state says” line
3. **premature certainty**: unresolved seams rewritten as stable judgment
4. **future amnesia**: no clear marker for where the danger in the seam actually was

## Minimal operator test

Before composing a mixed seam into stronger notebook prose, ask:

1. What exactly is official-primary here?
2. What is still attributed gloss rather than state line?
3. Has any second institutional or field receipt matured the seam?
4. If not, is the unresolved gap itself the most truthful object to preserve?

If the answer to `4` is yes, stop and packet first.
