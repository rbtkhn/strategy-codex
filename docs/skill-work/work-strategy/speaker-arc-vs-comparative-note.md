# Speaker Arc vs Comparative Note

WORK only; not Record.

This note gives the operational rule for when to write a **speaker arc** and when to write a **comparative note** above it.

## Short rule

Write a **speaker arc** when the notebook needs a compact, reusable note about a recurring **host x guest** run inside one stream.

Write a **comparative note** only when two or more speaker arcs already exist and the notebook now needs to preserve what changes across host conditions without flattening those host-local objects.

For a speaker folder itself, the minimum requirement is lighter only **after the folder is justified**: every canonical speaker folder needs a **routeable rationale**, not necessarily a speaker arc on day one. A routeable rationale may be a speaker object, profile, index, cross-host note, authored ledger, native stream map, or pointer to a substantial host-local arc in another folder.

Stricter shelf rule: if the speaker does not have enough real continuity, do **not** create the folder.

## Use a speaker arc when

Use a **speaker arc** when:

- one host stream has a real recurring guest run
- the notebook needs ranked entry points
- the lane has become reusable for routing
- the guest becomes legible through one repeated conversational setting

The object should stay:

- stream-local
- compact
- host-conditioned

Typical question:

- why does this recurring host x guest run matter?

## Use a comparative note when

Use a **comparative note** only when:

- at least two host-local speaker arcs already exist
- the comparison itself has become reusable
- the notebook needs to preserve how the same guest changes under different host pressure
- a higher-order contrast would help future routing more than another local arc

Typical questions:

- how does this guest change across hosts?
- what does this host stream uniquely do to its guests?
- what remains local, and what becomes comparable above the local layer?

## What not to do

Do **not** skip the speaker-arc layer and go directly to a comparative note.

Do **not** use a comparative note:

- after only one mature arc
- to avoid doing host-local ranking work
- to collapse different host-conditioned objects into one generic guest profile
- to create a stealth super-arc

Do **not** create a speaker arc merely because a speaker folder exists. If the evidence is thin, do not create the folder yet. If the folder is already justified but the continuity has not yet consolidated, preserve it with a routeable rationale and an explicit boundary instead.

## The boundary

A **speaker arc** preserves:

- local contour
- host-conditioned legibility
- compact routing value

A **comparative note** preserves:

- cross-host differential
- pressure-profile contrast
- second-order routing guidance

The arc stays primary.
The comparison sits above it.

## Practical sequence

1. Build the first speaker arc.
2. Build the second speaker arc if the form survives another host stream.
3. Only then ask whether the cross-host differential is itself worth preserving.
4. If yes, write a comparative note above the arcs without replacing them.

For lighter speakers, the practical sequence is:

1. Verify the speaker has enough real continuity to deserve a folder at all.
2. Write the routeable rationale.
3. Route materialized appearances to the correct source or host surface.
4. Create a host-local arc only after recurrence becomes useful.
5. If the speaker becomes major across hosts, contexts, or time, consolidate toward a canonical person arc.
6. Create a helix or comparative note only after multiple mature strands need comparison.
