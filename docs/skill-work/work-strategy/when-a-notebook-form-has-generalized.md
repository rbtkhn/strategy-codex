# When a Notebook Form Has Generalized

WORK only; not Record.

A notebook form has not truly generalized just because it survives repetition inside one stream.

It has generalized when all of the following become true:

- it survives in a second host ecology
- it remains useful under a different pressure profile
- it preserves local truth rather than flattening it
- it reveals a higher-order comparison without forcing early abstraction

The recent `speaker arc` expansion is a good example.

## What does not count as generalization

A form has **not** generalized merely because:

- one host uses it many times
- several files now share a template
- the operator likes the term
- it feels elegant

Those may indicate local success, but not form-level generalization.

In that weaker state, the object may still be:

- stream-specific
- convenience-driven
- naming polish rather than structural discovery

## What changed with speaker arc

At first, `speaker arc` could still be read as a strong Diesen-local solution:

- a better name than `canon note`
- a useful way to compress recurring guest lanes
- a compact routing object inside one mature host stream

That was already valuable, but it did not yet prove that the form itself was portable.

The change came when the object survived in `Dialogue Works`.

Two things mattered:

1. It worked for a host stream with a different pressure profile.
2. It did not produce the same kind of arc in every case.

That second point is the real test.

If the form had generalized only by making everything look alike, the notebook would have learned the wrong lesson.

Instead:

- `Dialogue Works × Marandi` became a pressure-register / red-line / legitimacy arc
- `Dialogue Works × Freeman` became a live statecraft / performative diplomacy / order-transition arc

So the form proved it could survive outside Diesen **without abolishing host-conditioned difference**.

## The real test

The real test of generalization is not:

- can this be reused elsewhere?

It is:

- can this be reused elsewhere **without losing what the elsewhere changes**?

That is the difference between:

- a portable notebook form
- and a flattening template

## Host-local truth still matters

`speaker arc` is still fundamentally host-stream-local.

That should not change.

The form works because it preserves:

- how one host repeatedly questions
- how one guest repeatedly answers
- how that interaction becomes reusable for future routing

So generalization does **not** mean:

- merging all host variants into one super-object
- inventing a guest-totality note too early
- treating repeated guests as if one host had exhausted their meaning

The local contour stays primary.

## What generalization reveals above the form

When a form truly generalizes, it often reveals a **second-order comparison layer** above itself.

In this case, that higher layer is not a bigger arc.

It is something like:

- cross-host guest differential
- host-pressure comparison
- conditioned legibility across streams

That higher layer should remain distinct from the arc itself.

The arc stays local.
The comparison sits above it.

If those two layers are confused, the notebook upgrades portability into flattening.

## Durable rule

Treat a notebook form as truly generalized only when:

1. it survives in another stream
2. it remains useful under different host pressure
3. it keeps the local contour intact
4. it creates a legitimate comparative layer above itself
5. that higher layer remains separate from the local object

## Practical implication

When this threshold is crossed:

- keep using the form locally
- do not collapse host variants into one object
- allow a comparative note above the form if needed
- update doctrine to say the form is now general, not merely founding-stream-specific

That is the right kind of notebook growth:

- more portable
- more comparative
- still resistant to flattening
