# Locals recipe — analysis to post

**Purpose:** Standardize the path from **strategy analysis** to a paste-ready **VivaBarnesLaw / Duran Locals** post. This is the missing middle between the existing **voice / craft doctrine** and the **shipping checklist**.

**Default target:** one **medium** Locals post with **one thesis spine**, **medium quote density**, and a **memorable declarative closer**.

**Use this when:** the input is already analytical and evidence-rich — a strategy pass, transcript analysis, notebook synthesis, historical context artifact, or **named-mind** analysis — and the task is to turn it into publishable Locals prose rather than keep it in notebook form.

## Valid source inputs

- strategy analysis reports
- notebook lines or `days.md` synthesis
- **named-mind** or **`statecraft-multi-lens`** output (not legacy **`tri-mind`** — [TRI-MIND-DEPRECATED.md](../skill-work/work-strategy/TRI-MIND-DEPRECATED.md))
- transcript / raw-input excerpts
- historical expert context artifacts

## Standard transform

### 1. Choose one post angle

Reduce the source set to **one public-facing claim**.

Good angles:
- one change over time
- one contradiction that matters
- one institutional or political mechanism
- one forecast fork

Bad angles:
- everything the source said
- all themes at once
- a notebook summary with the serial numbers left on

### 2. Reduce to one claim spine

Write one working sentence that states:
- what changed, or
- what the post is really about, or
- what the reader should carry away

If the draft cannot be summarized in one sentence, the angle is still too broad.

### 3. Select a small proof set

For Locals, proof should be **curated**, not exhaustive.

Default:
- 2 to 5 proof points
- several **short visible quotes**
- each quote should do a job:
  - name the shift
  - sharpen the contrast
  - establish the strongest phase break

Do not use the quote set as a transcript collage.

### 4. Draft in Grace-Mar Locals voice

Use the existing house style:
- open on the thing
- use proper nouns
- keep one spine
- explain in plain English
- let liability / mechanism appear when it earns the line

The prose should narrate the argument. The quotes should punctuate it.

### 5. Run shipping check

Before shipping, confirm:
- the first sentence states the argument, not the existence of an interview
- the post has one public-facing claim, not a notebook recap
- the quote density feels intentional
- the closer lands a thesis rather than re-listing phases

## Default Locals shape

For transcript-derived Locals posts, the default shape is:

1. topic-first lede
2. one medium body built around one claim spine
3. medium quote density
4. declarative closer

The default is **not**:
- a table
- a dossier
- a phase list
- a long blockquote stack

## Anti-patterns

- **Analysis dump:** preserving the internal structure of the notebook instead of writing for a forum reader
- **Notebook jargon:** equilibrium, planes, seam talk, or other repo-internal packaging
- **Full-table body:** date-by-date rows pasted into the public post
- **Transcript collage:** quote pile without a governing argument
- **False economy:** stripping all quotes until the argument becomes unsupported

## Optional follow-ons

After the Locals post exists, you may derive:
- one X trim
- one Predictive History comment

These are optional follow-ons, not required outputs of the standard workflow.
