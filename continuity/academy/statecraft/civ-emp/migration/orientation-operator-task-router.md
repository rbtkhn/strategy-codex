
# Helix-First Operator-Task Router
<!-- word_count: 1360 -->

## Purpose

Use this note as the third corpus-level orientation / retrieval surface for the helix-first statecraft layer.

The earlier retrieval notes answer two different entry questions:

- [orientation-helix-front-door.md](orientation-helix-front-door.md) helps when you do not yet know whether to begin with a lane or a family
- [orientation-problem-shape-router.md](orientation-problem-shape-router.md) helps when you already know the problem is cross-lane but need the right problem-shape

This note answers a third question:

- what should you read first when you already know what **job** you are trying to do

## Reading Posture

Read this note as an operator router, not as a substitute for the helixes, strands, synthesis notes, or meta-surfaces beneath it.

Its job is to reduce search friction once the corpus already contains:

- lane helixes
- strand surfaces
- canonical-family synthesis
- problem-shape routing
- architecture-class meta-surfaces

Use it when the need is practical and immediate: diagnosis, clause drafting, settlement design, escalation review, or lane comparison.

## Task Map

### 1. Diagnosis

Use this path when the main job is to identify what kind of object the live problem actually is before drafting, escalating, or comparing.

Typical signals:

- the situation is blurry and the real hinge has not been named yet
- you are unsure whether the problem is lane-carried or cross-lane
- several explanations are competing and you need the governing grammar first

Start with:

- [Helix-first front door](orientation-helix-front-door.md)
  Use when you are still deciding whether to begin with a lane helix or a cross-lane family note.
- [Helix-first problem-shape router](orientation-problem-shape-router.md)
  Use when you already know the issue is cross-lane and need to sort it into settlement-room, escalation-governance, or continuity and self-misread.

Then descend:

- to the relevant lane helix if one state's grammar is carrying the object
- or to the relevant family note if the hinge is already clearly shared across lanes

### 2. Clause Drafting

Use this path when the main job is to shape or stress-test an actionable clause, review mechanism, carrier, relief sequence, contact procedure, or bounded coercive ask.

Typical signals:

- the issue is no longer only interpretive; it needs operational language
- you need to know what must be carried, reviewed, guaranteed, or bounded
- the risk is writing a clause that sounds serious but has no real owner or stop condition

Start with:

- the governing lane helix if the clause belongs mainly to one state grammar
- or the governing synthesis note if the clause is already obviously cross-lane

Then descend:

- [Meta-synthesis: settlement-room architecture](canonical-family-settlement-room-architecture.md)
  Use when the clause is about peace ownership, review carry, access, or room inhabitability.
- [Meta-synthesis: escalation governance](canonical-family-escalation-governance.md)
  Use when the clause is about pressure, enoughness, reciprocal stop conditions, or living contact procedure.
- [Meta-synthesis: continuity and self-misread architecture](canonical-family-continuity-misread-architecture.md)
  Use when the clause is about inherited plausibility filters, continuity review, or correcting self-misread before pressure or settlement language hardens around a false carrying picture.

Finish in:

- the relevant strand object for the precise carrier logic
- then the lane or cross-lane `transactions/` surface if drafting needs spending, sequencing, or executable instrument logic
- then [Helix-first clause-review checklist](orientation-clause-review-checklist.md) before trusting the clause

### 3. Settlement Design

Use this path when the main job is to decide whether a proposed room, settlement, ceasefire, relief architecture, or recognition arrangement is actually inhabitable.

Typical signals:

- the proposed peace may be rhetorically attractive but architecturally thin
- inclusion is being claimed without access, relief, or review carry
- the real question is whether the room can survive succession and enforcement

Start with:

- [Canonical-family synthesis: real settlement](canonical-family-settlement-real.md)
- [Canonical-family synthesis: exclusion and direct settlement](canonical-family-exclusion-settlement.md)

Then widen to:

- [Meta-synthesis: settlement-room architecture](canonical-family-settlement-room-architecture.md)

Then descend to strands as needed:

- `peace` for review, relief, successor carry, and closure versus theater
- `geo` for corridors, access, chokepoints, and geographic room structure
- `empire-instrument` for guarantors, enforcement carriers, and bargaining leverage

### 4. Escalation Review

Use this path when the main job is to judge whether active pressure is still politically governed or is beginning to outrun its own stop conditions.

Typical signals:

- coercion persists without a bounded end state
- proxy or indirect pressure still looks usable even though contact procedure has thinned
- the operators know how to intensify but not how to stop credibly

Start with:

- [Canonical-family synthesis: coercion conversion](canonical-family-coercion-conversion.md)
- [Canonical-family synthesis: broken contact regimes and arms-control inheritances](canonical-family-broken-contact-regimes.md)

Then widen to:

- [Meta-synthesis: escalation governance](canonical-family-escalation-governance.md)

Then descend to strands as needed:

- `war` for coercive design, bounded enoughness, and escalation architecture
- `state-memory` when older danger memory or successor fear is distorting live judgment
- `empire-instrument` when the outward pressure stack itself is the real source of drift

### 5. Lane Comparison

Use this path when the main job is to compare how different lanes validate, falsify, carry, or deform the same problem.

Typical signals:

- the family note is already clear, but you need variance across lanes
- you are trying to compare carriers, review logic, or falsifiers rather than merely summarize one lane
- the next question is not "what is this family" but "how do the lanes diverge under the same family"

Start with:

- the relevant canonical-family synthesis note
- then the relevant meta-surface if the comparison belongs to one of the architecture classes

## Quick Operator Router

Use this shorter sequence when the work is moving fast:

1. **Need to name the object first?**
   Start with [orientation-helix-front-door.md](orientation-helix-front-door.md).

2. **Already know the object is cross-lane but not the kind?**
   Start with [orientation-problem-shape-router.md](orientation-problem-shape-router.md).

3. **Need to shape a clause, carrier, or sequence?**
   Start with the governing helix or family note, then move into the matching meta-surface.

4. **Need to decide whether a peace architecture is real?**
   Start with the settlement-design path.

5. **Need to judge whether live coercion is still governable?**
   Start with the escalation-review path.

6. **Need to compare lanes under one family or architecture class?**
   Start with the matching family note or meta-surface, then compare downward into helix-plus-strand differences.
