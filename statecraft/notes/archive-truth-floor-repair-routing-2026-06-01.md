## Purpose

This note names the current `statecraft` archive-truth seam as a machine object
rather than leaving it to appear as a raw technical-debt pile in the worktree.

Use it when the real question is not:

- which lane owns a live geopolitical object


## Core Claim

The open transcript-integrity seam is not one generic cleanup pass.

It is a **truth-floor repair stack** with distinct tranche types.

That matters because the current repo architecture now depends more heavily on
archive truth than it did in a looser accumulation phase.

## The Current Tranche Map

### 1. `Hormuz` audit tranche

This is the detection and evidence layer.

It includes:

- audit scripts
- tests for those scripts
- JSON and Markdown audit artifacts

Its job is to say:

```text
where are the likely mistranscriptions,
how strong is the confidence,
and which cases are direct versus contextual?
```

### 2. `Hormuz` direct repair tranche

This is the narrow phrase-family repair pass.

Its job is to say:

```text
apply only the bounded high-confidence fixes
for this one chokepoint phrase family
```

This tranche should remain explicitly narrower than the whole archive seam.

### 3. Common statecraft entity normalization tranche

This is broader than `Hormuz`.

It includes recurring entity families such as:

- `Xi Jinping`
- `Wang Yi`
- `Bandar Abbas`
- `Napolitano`
- `Witkoff`
- `Kharg`
- `Hegseth`

Its job is to normalize high-confidence recurring entity garbles across the
statecraft transcript corpus.

### 4. Shared replacement-substrate tranche

This is optional and should not be silently absorbed into the three tranches
above unless the dependency is truly minimal.

Its job is to answer:

```text
are we repairing the statecraft archive,
or are we refining the broader ASR replacement substrate that statecraft happens to use?
```

If the latter is true, it deserves its own boundary.

## Opening Rule

When the archive-truth seam is live, open the stack in this order:

1. audit tranche first
2. direct bounded repair tranche second
3. broader entity normalization tranche third
4. shared replacement-substrate refinement only if required

If the current family already has a clean `before -> repair -> after -> remainder`
arc and the remainder is zero or explicitly reviewed, stop there and open the
next tranche instead of searching for more local cleanup.

For the compact reusable receipt shape, open [Archive Truth-Floor Audit Receipt Pattern](../../docs/archive-truth-floor-audit-receipt-pattern.md).

Do not narrate this seam as:

- one giant repair blob
- one accidental worktree mess
- or one proof that archive work is somehow outside the machine

The honest read is:

```text
archive truth-floor repair is now one of the machine's own governed subfunctions
```
