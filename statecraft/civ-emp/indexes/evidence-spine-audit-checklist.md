# Evidence Spine Audit Checklist

WORK only; not Record.

Use this note to falsify shallow CIV-EMP objects before any scripting or automated enforcement.

## Purpose

This checklist measures whether a CIV-EMP object is actually **connection-built**.

Use it when reviewing:

- Sacred Grammar case files
- lane-local `god`, `lit`, `art`, and `state-memory` objects
- bridge-state or continuity-comparator notes
- source retrieval outputs that claim to be full-strength rather than `Provisional`

## Minimum Evidence Spine

A serious CIV-EMP object should name:

- **Seed MEM**
- **MEM CONNECTIONS cluster**
- **Overview corroborators**
- **Counterweight**
- **Current-carrier bridge**

If one of those is missing, the object is not full-strength yet.

## Quantitative Receipts

Record these counts when the construction matters:

- **Seed MEM count**
- **Total traversed MEM count**
- **Rupture-stage coverage**
- **Counterweight count**
- **Current-carrier relation present or missing**

This is a human-readable audit, not a score machine. The counts exist to distinguish thick objects from elegant summaries.

## Falsification Rules

Treat the object as shallow, weak, or still `Provisional` if any of these are true:

- no seed MEM is named
- no `MEM CONNECTIONS` usage is visible
- no counterweight is named
- no current-carrier relation is named
- the object was built from one `CIV-CORE-*` overview alone
- the object describes themes but does not relate them to rupture or present carriage

## Quick Pass

Ask these five questions:

1. What is the seed MEM?
2. Which connected MEMs changed or complicated the first reading?
3. What overview files corroborated the read without replacing the graph?
4. Where does the pattern fail, harden, or overreach?
5. Who or what carries the pattern now?

If the object cannot answer those cleanly, route back through the retrieval matrix before treating it as mature doctrine.
