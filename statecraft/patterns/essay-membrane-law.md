# Essay Membrane Law

WORK only; not Record.

Purpose: name how a multi-term civ-state volume should layer **essays** so
operators and agents do not conflate constitutional continuity, single-dimension
history depth, and multi-lens friction reads.

## When To Use

Use essay-membrane law when:

- a volume has **multiple `{civ}-{term}.md` theory files** with parallel segment
  stacks and cross-read membranes
- essay demand splits three ways: volume Parts prose, one-spine history depth,
  and "same node × all lenses" demonstrators
- agents keep misrouting into the wrong essay class or duplicating term rosters
  inside essays

## The Three Tiers

Separate these before writing or promoting any essay:

| Tier | Job | Must not |
|------|-----|----------|
| **Constitutional** | Transformed continuity · outward machinery (volume Parts 1–2) | Replace term-file SSOT or own rupture-primary rows |
| **History sub-lenses** | One parallel dimension at essay depth | Own rupture-primary or a full six-lens read |
| **Hexagonal demonstrators** | One friction node × six term lenses | Duplicate rosters; re-encode term files |

This solves: "The essay is coherent, but it is doing constitutional work,
history work, and routing work at once."

This is not: a ban on cross-links between tiers — each tier **links back** to
term SSOT and to the routing map.

## Routing SSOT Sequence

Before wave encoding, stand up this sequence (order matters):

```text
connectivity essay (operator map)
  → hexagonal template (copy scaffold)
  → essays registry (wave checklist + status)
  → essay bodies
  → term-file Bridge blocks (entry from any lens)
```

The connectivity essay is **routing map**, not a seventh term file. Term files
remain roster and segment SSOT; essays **link segment anchors only**.

## Prep-Before-Encode

Multi-essay waves need **template + empty registry + essay-type prose + Bridge
pointers** before the writing session.

This solves: each agent reinvents shape and misroutes into constitutional or
history essays.

This is not: a requirement to ship all demonstrators in one commit — only that
**scaffold ships before bodies**.

## Placement Checks

Before appending or promoting an essay, ask:

```text
Which tier owns this job?
Does any roster row already live on a term file?
Is rupture-primary on the correct home (entropy vs faith exception)?
Does this duplicate a constitutional or history essay's primary claim?
```

## What Counts As Misuse

The pattern is being misused when:

- a hexagonal demonstrator **extends rosters** instead of linking anchors
- a history sub-lens essay **owns rupture-primary** that belongs on entropy
- a constitutional essay **replaces** `{term}.md` segment tables
- connectivity prose **accumulates narrative depth** that belongs on term files
- essay-type labels are omitted and agents default to "one big Rome essay"

## Statecraft Reuse Rule

```text
When a multi-term volume earns an essay layer,
declare three tiers by job;
stand up connectivity + template + registry before demonstrator encode;
essays link term SSOT — they do not extend rosters or duplicate rupture-primary.
```
