# PH-CIV Era Overlay Options

This note preserves possible ways to overlay the CIV-STATE era structure onto `ph-civ` in the future.

The governing caution is simple:

`use CIV-STATE eras as a reading lens, not as a forced rewrite of PH-CIV's native structure`

`ph-civ` already has its own chapter logic, route logic, and public narrative architecture. Any era overlay should add comparative clarity without flattening that architecture into bibliography logic.

## Governing Principle

The best overlay should do three things:

- increase comparative readability across civilizations
- preserve `ph-civ`'s native narrative order
- remain clearly secondary to the public manuscript's own structure

The main thing to avoid is making the era scaffold so dominant that `ph-civ` stops reading like `ph-civ`.

## Possible Overlay Shapes

### 1. Tag Overlay

Add era tags to `ph-civ` objects without changing chapter order:

- `Ancient`
- `Medieval`
- `Colonial`
- `Industrial`
- `Cybernetic`

This is the lightest version. It improves filtering and cross-civilizational comparison without disturbing the manuscript.

### 2. Route Overlay

Create reader routes that traverse existing `ph-civ` material through the CIV-STATE clock, for example:

- Rome through the five eras
- late-opening civilizations
- industrial-to-cybernetic transitions
- the `1991` boundary across civilizations

This keeps the base artifact intact while enabling era-based traversal.

### 3. Companion Essay Overlay

Add short interpretive notes at the volume or route level explaining:

- what the era means in this civilization
- where the hard hinges are
- what changes in sovereignty form across the eras

This would function as a public-facing cousin of the CIV-STATE shelf-reader layer.

### 4. Card-Level Metadata Overlay

Attach compact era-facing fields to `ph-civ` cards, such as:

- `era`
- `era_hinge`
- `continuity_form`
- `rupture_type`

This would make the era structure queryable and comparable across the corpus without rewriting chapter prose.

### 5. Parallel Index Overlay

Build a separate PH-CIV era index that points into existing `ph-civ` content by era without editing the core manuscript structure.

This is probably the cleanest strong version because it creates a real comparative surface while leaving the manuscript untouched.

## Likely Preference Order

If this is pursued later, the strongest sequence is probably:

1. tag overlay
2. parallel index overlay
3. route overlay
4. card-level metadata overlay
5. companion essay overlay

That order keeps the first moves light, reversible, and low-risk.

## What To Avoid

Avoid:

- forcing every `ph-civ` chapter into the same era template
- flattening lecture logic into bibliography logic
- making CIV-STATE chronology more important than the manuscript's own narrative logic
- using the overlay to silently rewrite public `ph-civ` scope

The overlay should clarify, not conquer.

## Decision Standard

If a future overlay is built, judge it by this question:

`does this make PH-CIV more navigable and comparable without erasing PH-CIV's native architecture?`

If yes, it may be worth keeping. If not, the overlay is too heavy.
