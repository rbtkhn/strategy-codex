WORK only; not Record.

This file is a delegated module under [statecraft.md](statecraft.md). It owns maturity checks, anti-sprawl rules, lifecycle closure, and stable-versus-experimental governance. It does not redefine the system’s ontology or protocols.

## Stable Line

Statecraft is a drafting system. It converts historical pattern, contemporary speaker-state input, and lane-specific judgment into treaty clauses, policy papers, negotiation briefs, crisis memos, transaction-use briefs, and reusable statecraft transactions.

The stable sequence is:

1. `civ-emp` retrieval supplies recurrence, memory, counterweight, and transaction hook.
2. Lane routing identifies the correct owner or comparison frame.
3. Lane doctrine converts the crisis into one actor’s state interest, fear, leverage, constraints, and preferred instrument.
4. Drafting method converts the object into a bounded artifact.
5. Reviewable candidates feed durable discoveries back either to lane update surfaces or to the `civ-emp` review queue.

## Maturity Checks

Use these checks before calling a lane, sheet, or transaction mature:

1. **Entry clarity** - can a new operator tell where to start and what the next surface is?
2. **Carrier clarity** - does the artifact name the implementation burden and authority carrier?
3. **Settlement clarity** - does it identify the real settlement spine rather than themes alone?
4. **Revisit discipline** - does it include falsifiers, review triggers, or score-moving conditions?
5. **Comparative usefulness** - can the object be compared across lanes or reused later?
6. **Recursive usefulness** - does the work teach either the lane or `civ-emp` something durable?

## Promotion Threshold

Do not promote by momentum.

A statecraft object should usually become a lane draft or full transaction only when it has:

- a distinct crisis object
- a real settlement spine
- named authority carriers
- a plausible instrument form
- limited aim and restraint logic
- falsifiers, review triggers, or revisit discipline

If the work is still mostly interpretation, warning, analogy, or pressure description, it is healthier as commentary, braid, memo, comparison, objection matrix, router candidate, or transaction-use brief.

## Failure Modes

- commentary inflation
- template theater
- lane encyclopedism
- transaction overproduction
- threshold evasion
- speaker capture drift
- recursive fiction
- cross-lane blur
- source-memory bleed from live drafting back into `civ-emp`
