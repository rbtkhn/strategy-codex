# Statecraft Archive and Statecraft Synthesis

Purpose: define the canonical two-layer naming pair for the source and speaker stack that feeds live repo-root `statecraft/`.

Use this note when the real question is not yet lane choice or drafting, but rather what kind of layer you are opening and what authority it actually carries.

## Vertical Law

Read the stack in this order:

`Statecraft Archive -> Statecraft Synthesis -> host law / bridge conditioning -> CIV-STATE retrieval -> lane drafting`

This law is architectural, not ornamental.

- `Statecraft Archive` preserves source truth.
- `Statecraft Synthesis` interprets that truth into coherent speaker-side objects.
- host law and bridge conditioning change retrieval posture without replacing archive or synthesis.
- `civ-state` retrieves deep comparative pattern memory for the live object.
- lanes own drafting, instrument choice, and settlement-bearing output.

## Definitions

### Statecraft Archive

The canonical source-bearing layer for live statecraft work: transcript-bearing captures, provenance-bearing captures, raw-input bundles, and source-complete evidence preserved for retrieval, audit, and downstream interpretation.

Its current underlying path remains [`source-archive/statecraft/`](/C:/dev/strategy-codex/source-archive/statecraft).

### Statecraft Synthesis

The first coherent interpretive layer above the archive: speaker continuity, routing, crossing, support, and bounded synthesis surfaces that assemble archive truth into usable statecraft objects without replacing it.

Its primary home is [`statecraft/speakers/`](/C:/dev/strategy-codex/statecraft/speakers/README.md).

## Boundary Law

Statecraft Archive preserves source truth. Statecraft Synthesis interprets that truth. Neither host law, bridge conditioning, CIV-STATE retrieval, nor lane drafting should be mistaken for the archive itself.

Keep these boundaries strict:

- the archive does not synthesize
- synthesis does not pretend to be raw-text authority
- host law does not replace speaker continuity
- bridges do not replace synthesis
- `civ-state` does not replace transcript truth
- lanes do not silently redefine upstream source authority

## What Belongs In Each Layer

### Statecraft Archive

- transcript captures
- provenance-bearing source captures
- raw-input bundles
- source-complete archive indexes
- archive-local route maps whose primary job is evidence access

### Statecraft Synthesis

- speaker arcs
- routing notes
- helixes and crossing surfaces
- support spines
- bounded month-support shelves
- speaker-side synthesis notes that assemble archive truth into a stable object

## Subfunctions, Not Rival Layer Names

These existing terms still matter, but they are subordinate functions inside the larger pair:

- `raw-text authority`
- `provenance bench`
- `source-bearing full captures`
- `whole-speaker continuity`

Use them locally when they remain the sharpest name for a file or function. Do not let them compete with the top-level pair.

## Opening Rule

When a live statecraft problem needs grounding:

1. open the strongest relevant source in the **Statecraft Archive**
2. extend into **Statecraft Synthesis** only after the source ground is real
3. move into host law, bridges, CIV-STATE, or lanes only when the question has actually changed

This is the constitutional guard against polished routing that has lost contact with transcript truth.
