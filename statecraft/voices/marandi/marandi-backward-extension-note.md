# Marandi backward extension note

WORK only; not Record.

Purpose: define the governed path for extending the Marandi shelf farther backward if additional 2025 material is later captured.

## Rule

Do not create a second top-level Marandi continuity system when earlier material appears.

Backward extension should refine the existing stack, not fork it.

## Extension order

If meaningful earlier material is added:

1. update [marandi-source-index.md](marandi-source-index.md)
2. reassess [marandi-cross-year-note.md](marandi-cross-year-note.md)
3. update [marandi-2025-present-arc-threads.md](marandi-2025-present-arc-threads.md) only if the earlier material truly changes recurring thread boundaries
4. update [arc-marandi-continuity.md](marandi-arc.md) only if the maturity story or speaker-wide motion materially changes

## What not to do

- do not create a second thread atlas for pre-2026 material
- do not create a competing root continuity note
- do not treat every older capture as equally weight-bearing merely because it extends the date range
- do not collapse mature spring 2026 density into a falsely flat cross-year chronology

## Boundary

Backward extension is allowed. Duplicate continuity spines are not.
