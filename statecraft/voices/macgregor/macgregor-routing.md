# Macgregor routing

WORK only; not Record.

Purpose: make the Macgregor speaker object faster to route without duplicating host chronology. This note answers a narrower question than the helix note: **which host lane or monthly synthesis shelf should the Codex open first for a given kind of Macgregor use**.

## Core rule

Macgregor now has a native 2026 monthly shelf layer, but it is **bounded synthesis**, not chronology ownership. The efficient structure is:

- host shelves hold chronology
- the speaker shelf holds object identity
- the support spine holds maturity and month-status law
- monthly shelves hold bounded monthly synthesis
- host-local speaker arcs still do the main routing work

So this note is the **speaker-side index** into the real Macgregor host lanes and the new bounded monthly shelves.
