
# Ritter Historical Themes

Purpose: hold the speaker-side historical-theme commentary surfaces for the bounded `2025-01-01 -> present` Ritter shelf once recurring theme families are clear enough to promote.

This front door exists in the current migration wave even though no individual Ritter theme files are being promoted yet.

## Why the folder exists now

The shelf now needs the historical membrane in place because:

- `civ-state` is part of the canonical Ritter statecraft shelf architecture
- future hardening will likely promote recurring historical-example families
- the migration should establish the membrane before it starts multiplying theme files

## Promotion rule

Create an individual Ritter theme file only when:

- the historical-example family is explicit in materialized Ritter raw-input
- the argumentative use recurs clearly enough to form a real theme family
- the file would hold a recurring pattern family rather than one named example

## Current state

No individual Ritter theme files are promoted in this wave.

Use [ritter-historical-examples-audit.md](ritter-historical-examples-audit.md when the task is:

- deciding whether a recurring Ritter historical family is real enough to promote
- scoring route families before creating speaker-side theme files
- deciding whether a future `civ-state` companion scaffold is justified

## Boundary

- These files are speaker-side commentary surfaces, not transcript authority.
- These files are not `civ-state` objects; they stay on the Ritter side of the membrane.
- Do not create one file per named example. Each file should hold a recurring theme family.
