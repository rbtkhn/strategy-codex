# Persia Recognition-Vs-Settlement Bridge

WORK only; not Record.

Purpose: regulate the transition between speaker-conditioned Iran retrieval and Persia lane drafting when the real uncertainty is still whether the object should be read recognition-first or settlement-first.

## Trigger

Open this bridge when Persia/Iran already owns the object and the remaining uncertainty is:

- whether the live claim is mainly about dignity, legitimacy, sovereignty, and recognition leakage
- or whether it is already mainly about guarantees, sequencing, institutional durability, and settlement architecture

If lane ownership is still unclear, do not use this bridge yet.

## What This Bridge Chooses

This bridge chooses retrieval posture, not lane ownership and not final drafting form.

- **Recognition-first** -> use the [Marandi adapter](marandi-civ-emp-retrieval-adapter.md)
- **Settlement-first** -> use the [Parsi adapter](parsi-civ-emp-retrieval-adapter.md)

## Recognition-First Rule

Use the Marandi-weighted path when the live claim is still primarily about:

- humiliation, dignity, victimhood, or anti-subordination language
- endurance becoming legitimacy
- sovereignty under coercion
- Hormuz or pressure becoming politically meaningful recognition
- whether pressure is already leaking recognition to Iran

Return to the Persia lane once the recognition threshold is clear enough to test whether it can be converted into mechanism, relief, or restraint.

## Settlement-First Rule

Use the Parsi-weighted path when the live claim is already primarily about:

- guarantees and implementation realism
- sanctions relief sequencing
- blockade failure and bargaining architecture
- regional settlement design
- whether leverage can survive institutionalization

Return to the Persia lane once the settlement question is clear enough to identify the governing strand, carrier problem, or transaction family.

## Return Path

After the adapter run:

1. return to [Iran helix](../persia/helix.md) if the integrated line still needs restoration
2. return to [Iran state](../persia/state/) if current carriers now govern the next move
3. return to [Persia transactions](../persia/transactions/) if the object has truly crossed into clause or mechanism work

## Mistake This Bridge Prevents

This bridge exists to prevent two recurrent errors:

- treating speaker shelf or adapter retrieval as if it were already Persia lane drafting
- jumping directly into clause language before the retrieval posture has been resolved

Speaker-conditioned retrieval is an input discipline. The Persia lane still owns the draft.
