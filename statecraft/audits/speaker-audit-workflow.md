# Speaker Audit Workflow

Use this note when the audit hub is conceptually clear but the next operator move is not.

The goal is to keep `credibility` and `accuracy` separate while making both easier to populate in a repeatable way.

## Fast Router

Open the right audit surface first:

- open [speaker-credibility-matrix.md](speaker-credibility-matrix.md) when the question is `how much provisional trust should we extend before closure?`
- open [speaker-accuracy-ledger.md](speaker-accuracy-ledger.md) when the question is `what happened to a bounded claim after review?`
- open [speaker-credibility-accuracy-bridge.md](speaker-credibility-accuracy-bridge.md) when the notebook is starting to confuse methodological trust with forecast performance
- open a per-speaker profile in `credibility/` or `accuracy/` when the shared matrix or ledger is too compressed

## Five-Step Workflow

1. **Find primary anchors**
   - start with raw transcript, raw input, or primary document
   - only lean on shelf synthesis after the primary anchors are visible

2. **Classify correction behavior**
   - assign the correction taxonomy before judging trust
   - keep `admission`, `hedge`, and `conditionality` separate

3. **Score credibility factors**
   - use the six shared factors:
     - self-correction
     - falsifier discipline
     - mechanism clarity
     - evidence posture
     - scope honesty
     - host consistency
   - if needed, add 1 to 2 native adjustment notes inside the speaker profile only

4. **Select bounded claims**
   - choose claims that are repeated enough to matter, specific enough to test, consequential enough to affect reuse, and sourceable to a stable file
   - avoid casual side remarks, pure mood, or giant civilizational statements that cannot yet close

5. **Assign accuracy status**
   - score each claim row with:
     - status
     - testability weight
     - short closure note
   - do not force unresolved claims into fake precision

## Source Order

Prefer this order:

1. raw transcript / raw input / primary document
2. canonical speaker shelf file that clearly cites primary material
3. compact routing or arc file
4. meta-summary or audit surface

## Reuse Rule

Use the hub to calibrate reuse burden, not to rank prestige.

- `credibility` tells the notebook how much cleanup is needed before reuse
- `accuracy` tells the notebook whether that provisional trust is being earned over time

## Common Failure Modes

- treating one `I was wrong` as a full correction habit
- treating `I hope I'm wrong` as equivalent to revision
- treating agreement with the notebook as credibility
- treating a broad unresolved macro claim as a clean `hit`
- punishing rhetorical heat even when the mechanism and evidence posture remain strong
- hiding speaker-specific nuances inside the shared matrix instead of declaring them in the profile notes
