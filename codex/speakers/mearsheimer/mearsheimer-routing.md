# Mearsheimer routing

WORK only; not Record.

Purpose: make the Mearsheimer speaker object faster to route without duplicating host chronology. This note answers a narrower question than the helix note: **which host lane should the Codex open first for a given kind of Mearsheimer use**.

## Core rule

Transcript-first evidence, arc-first interpretation.

For transcript-led Mearsheimer analysis, open the strongest actual transcript or transcript-bearing raw-input first, then use the host-local arc to interpret the host-conditioned transformation. Extend into this routing note, the helix, or broader synthesis only after the transcript and arc layers, and preserve the seam when synthesized claims go beyond transcript truth.

Mearsheimer does **not** need a native monthly shelf of his own. The efficient structure is:

- host shelves hold chronology
- the speaker folder holds object identity
- host-local speaker arcs do the primary routing work
- the raw-input index holds the current `non-core appearance bench`
- the Napolitano lane should be read as reinforcing orbit unless it later earns fuller structural status

So this note is the **speaker-side index** into the real Mearsheimer host lanes.

## Routing order

When the task is not already stream-specific, route Mearsheimer in this order:

1. open the strongest core host lane if the question is clearly `Diesen` or `Davis` shaped
2. open `Napolitano x Mearsheimer` only when the question is specifically defeat-accounting, boxed-in sequence control, or compact anti-war reinforcement
3. open the [raw-input index](mearsheimer-raw-input-index.md) when the relevant appearance lives outside the stable host core or when authored / non-core bench material is the real entry

This is the main reason Mearsheimer remains a codex-side exception shelf rather than a statecraft-native month ladder.
