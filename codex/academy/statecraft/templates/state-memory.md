# State Memory Template

WORK only; not Record.

Use this template for civilization-layer objects that store durable state-authority memory. A state-memory object is not a biography, not a current officeholder profile, and not a transaction. It names the long authority pattern that current state carriers inherit.

## Continuity Pattern

Name the authority pattern that survives regime, dynasty, party, constitutional, or leadership changes.

## Authority Forms

List the major historical forms that carried the pattern: monarchy, party-state, republic, clerical authority, council, security state, federation, administrative state, or other recurring surfaces.

## Current Carriers

Link the present `state/` files that carry the pattern now. Keep current carriers in `state/`, not in `civilization/`.

## Transaction Test

Before a transaction treats a clause as carryable, ask:

1. Does the clause preserve the durable state interest named by the memory object?
2. Which current carrier must authorize, implement, sell, or restrain it?
3. What historical wound, dignity claim, legitimacy grammar, or continuity burden does the wording touch?
4. What would make the settlement look like collapse, humiliation, overreach, or managed dependency?
5. What observable mechanism proves the carrier can implement after the headline moment?

## Failure Mode

Name how state memory can deform: paranoia, humiliation lock, endless sacrifice, overextension, succession fragility, personalism, factional veto, or refusal to convert leverage into settlement.

## CIV-MEM Inputs

Name the upstream CIV-MEM, archive, or lane-local civilization files used to ground the object. Keep this as provenance, not as a license to edit CIV-MEM from statecraft.
